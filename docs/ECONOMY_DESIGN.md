# Economy design and acceptance status

The existing economy uses integer minor units (100 per coin), UUID-owned purse/bank accounts, a ledger, and price/time order matching. Buy orders reserve coins; sell orders reserve assets. Partial fills create durable claims. Cancellation refunds the remaining escrow, never a filled portion. Auction items retain serialized Paper metadata; bidding reserves funds and creates a refund claim for the previous highest bidder. Expiry settles once. Existing database tests cover these business operations.

The player order book and funded NPC pool remain separate. New enchanted/custom commodities have distinct canonical asset IDs, even when their visible material is paper. New products start with zero NPC stock/budget; registration creates no executable player offers. Market prices need an actual counter-order. Legacy market settings in `config/server-baseline/NexoraTrading/market.yml` are the verified production reference.

General inventory operations now write a before/after snapshot before changing playerdata. Recovery resolves against the owner-scoped business receipt, saves the selected snapshot, and only then deletes the journal. This covers normal commodity selling, NPC selling, auction listing, item claims and minion transfer. Crafting has a durable commit marker. Pending recovery failures disconnect the affected player. Database recovery tests and real Paper serialization checks exist; crash injection with a real client is still required. Standardized Rocket sells also use the journal. Migration V6 adds owner/request-bound replay receipts and removes historical instance uniqueness that previously prevented legitimate resale; only one pending claim and one active market reservation per instance are allowed.

SQLite Core writers acquire IMMEDIATE transactions before reads that determine writes; busy timeout is 10 seconds. WAL and FULL synchronous durability remain enabled. Failures propagate and roll back. This correctness policy does not make blocking server-thread SQL acceptable: moving all remaining gameplay database work off-thread is an outstanding Foundation gate.

Balancing is not accepted yet. NPC values for newly registered items default to zero and are not automatically sold. Existing minions still have coin-based tier upgrades; fuel, material upgrades, hoppers and unique-type slot progression are unfinished. No five-archetype simulation or 30-player economy/load acceptance is claimed. Before enabling extra coin sources, simulate production, fees, upgrade sinks and complete restore/crash drills.
